仓库治理规则：
- 单一事实源：所有自研工具只在 susu-tools 内开发维护；
  原独立仓库（knowledge-publisher / ppt_doctor / QingTong / bg-skin）已迁移归档，不再回改。
- 新工具默认进 projects/（kebab-case 命名），先孵化后毕业：
  长大到需要独立身份 / 独立发版 / 有外部用户时，再迁出独立仓库（用 git filter-repo 保留历史）。
- 版本发布统一用 tag + GitHub Release，命名 <project>-v<semver>（如 bg-skin-v0.5.1）。
- 安全红线：API key / cookie / *.db / 运行时（python310、models、node_modules）一律不入库；
  提交前跑 scripts/secrets_scan.py 确认干净。
